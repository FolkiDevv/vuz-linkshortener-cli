# LinkShortenerCLI

Консольный сервис сокращения ссылок на Java: короткие коды, лимит переходов, время жизни ссылок с фоновой очисткой,
несколько пользователей с идентификацией по UUID и правами владельца на изменение и удаление.

## Установка и запуск

Нужны JDK 26 и Maven 3.9+.

```bash
mvn package
java -jar target/link-shortener.jar
```

`mvn package` компилирует код (с Error Prone и NullAway), прогоняет тесты и собирает исполняемый jar со всеми
зависимостями. Быстрая сборка без тестов и проверки форматирования — `mvn package -Pquick`.

Данные хранятся в `storage.json`, лог — в `shortener.log` (оба файла создаются в рабочей папке).

## Конфигурация

Настройки лежат в `src/main/resources/config.properties`. Их можно переопределить, положив файл `config.properties`
в рабочую папку (рядом с jar): значения из него перекрывают встроенные.

| Ключ                                | По умолчанию       | Что задаёт                                 |
|-------------------------------------|--------------------|--------------------------------------------|
| `shortener.baseDomain`              | `http://localhost` | домен, который показывается перед кодом    |
| `shortener.linkLength`              | `6`                | длина короткого кода                       |
| `shortener.cleanupInterval.seconds` | `60`               | период фоновой очистки просроченных ссылок |
| `link.ttl.seconds`                  | `86400`            | время жизни ссылки по умолчанию            |
| `link.useLimit`                     | `10`               | лимит переходов по умолчанию               |
| `storage.path`                      | `storage.json`     | путь к файлу хранилища                     |

Если файла нет, ключ отсутствует или значение некорректно (не число, ноль, отрицательное), берётся значение
по умолчанию из таблицы, а в лог пишется предупреждение.

## Команды

| Команда                              | Описание                                                          |
|--------------------------------------|-------------------------------------------------------------------|
| `create <url> [--limit N] [--ttl T]` | сократить ссылку                                                  |
| `open <short>`                       | перейти по ссылке (можно передать код или полную короткую ссылку) |
| `list`                               | показать свои ссылки                                              |
| `edit <short> [--limit N] [--ttl T]` | изменить лимит и/или TTL своей ссылки                             |
| `delete <short>`                     | удалить свою ссылку                                               |
| `whoami`, `login <uuid>`, `register` | текущий пользователь, вход под другим UUID, новый пользователь    |
| `help`, `exit`                       | справка, сохранение и выход                                       |

TTL задаётся числом секунд или с суффиксом `s`/`m`/`h`/`d` (`90`, `30m`, `2h`, `7d`). При `edit` новый срок
отсчитывается от текущего момента.

## Архитектура

```
folki.dev
├── Main                    — только собирает зависимости и запускает CLI
├── cli                     — интерфейс пользователя
│   ├── CliApp              — цикл ввода, разбор команд, вывод
│   ├── Command             — разбор строки «команда аргументы --опция значение»
│   ├── CliInteraction      — ввод/вывод через консоль
│   └── SoutNotifier        — уведомления в консоль
├── core                    — модели и бизнес-логика
│   ├── entities            — User, Link
│   ├── exceptions          — AppException и её наследники (понятные сообщения для пользователя)
│   └── services            — LinkService, CodeGenerator/RandomCodeGenerator, UrlValidator
└── infra                   — инфраструктура
    ├── config              — Config, PropertiesConfig, ShortenerSettings
    ├── storage             — Storage, FileStorage (JSON)
    ├── browser             — Browser, DesktopBrowser
    ├── CleanupScheduler    — фоновая очистка на ScheduledExecutorService
    ├── LoggingConfig       — настройка java.util.logging
    └── Notifier
```

Зависимости передаются через конструкторы и интерфейсы: `LinkService` получает `Storage`, `CodeGenerator`,
`Notifier` и `Clock`, `CliApp` — `Interaction` и `Browser`. Поэтому в тестах их легко подменить: фиксированный
генератор кодов, ручные часы, список вместо консоли.

### Принятые решения

- **Генерация кодов.** Случайная строка Base62 фиксированной длины (`SecureRandom`). Код проверяется по хранилищу, и при
  коллизии генерируется заново (не больше 10 попыток, затем понятная ошибка). Так как каждый код уникален глобально,
  одна и та же длинная ссылка у разных пользователей автоматически получает разные короткие.
- **Хранилище.** JSON-файл через Gson: в памяти `Map<UUID, User>` и `Map<String, Link>`, на диск — после каждого
  изменения. В файле хранится
  только код ссылки, домен подставляется при выводе — смена `baseDomain` ничего не ломает.
- **Лимит переходов.** `clickCount` — `AtomicInteger`, проверка лимита и инкремент делаются одной атомарной операцией
  (`getAndUpdate`), так что параллельные переходы не превысят лимит. Ссылка с исчерпанным лимитом считается неактивной;
  если владелец поднимет лимит, она снова станет активной.
- **TTL.** Время берётся из подменяемого `Clock`. Просроченная ссылка не открывается, даже если фоновая очистка ещё не
  сработала: срок проверяется при каждом переходе.
- **Потокобезопасность.** Фоновая очистка работает в отдельном потоке, поэтому методы `LinkService` и `FileStorage`
  синхронизированы.
- **Ошибки.** Все ожидаемые ошибки — наследники `AppException` с текстом для пользователя; CLI выводит их как
  `ОШИБКА: ...`. Непредвиденные исключения логируются, пользователь видит короткое сообщение без stacktrace.
- **Логирование.** `java.util.logging` в файл `shortener.log`, чтобы лог не смешивался с выводом CLI. Уведомления для
  пользователя идут через `Notifier`.

## Тестирование

```bash
mvn test
```

47 тестов на JUnit 5:

- `RandomCodeGeneratorTest` — длина и алфавит кода, случайность, проверка аргументов;
- `LinkServiceTest` — разные ссылки у двух пользователей на один URL, повторная генерация при коллизии, лимит (4-й
  переход при лимите 3 отклоняется), параллельные переходы, TTL на ручных часах, фоновая очистка, права владельца,
  валидация URL и границ, изоляция пользователей;
- `CommandTest` — разбор команд, опций и TTL, ошибки ввода;
- `ShortenerSettingsTest` — чтение конфига, значения по умолчанию, переопределение внешним файлом;
- `FileStorageTest` — сохранение и загрузка, повреждённый файл;
- `LinkLifecycleIntegrationTest` — сценарии целиком с настоящими часами и фоновой очисткой: «создал, открыл N раз,
  получил блокировку», «создал, подождал TTL, ссылка исчезла», «чужой пользователь не может удалить».

## Качество кода

- `mvn verify` дополнительно запускает `spotless:check` (palantir-java-format); исправить форматирование —
  `mvn spotless:apply`.
- Компиляция идёт с Error Prone и NullAway (null-безопасность через аннотации jspecify).
- GitHub Actions (`.github/workflows/ci.yml`) на каждый push и pull request выполняет `mvn verify` и сохраняет jar
  как артефакт.
- `.editorconfig` задаёт кодировку, отступы и переводы строк.
