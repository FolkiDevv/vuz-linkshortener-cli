# Чек-лист: консольный сокращатель ссылок (Java)

Всего 50 баллов: основные функции — 30, расширенные функции — 10, качество разработки — 10.

## Основные функции (30)

### 1. Сокращение и уникальность ссылок (5)

- [ ] Генерация короткого кода (Base62 от счётчика или случайный код с проверкой на повтор).
- [ ] Короткая ссылка уникальна для каждого пользователя: одна и та же длинная ссылка у двух пользователей даёт разные
  короткие.
- [ ] При коллизии код перегенерируется (цикл с проверкой по хранилищу).
- [ ] Тест: два пользователя сокращают один URL и получают разные ссылки.

### 2. Редирект из консоли (2)

- [ ] Команда `open <short>` вызывает `Desktop.getDesktop().browse(URI)`.
- [ ] Запасной вариант, если `Desktop` недоступен (например, на сервере): вывести URL в консоль.
- [ ] Проверка перед открытием: ссылка существует, не истекла, лимит не исчерпан.

### 3. Лимит переходов (5)

- [ ] У ссылки есть поля `maxClicks` и `clickCount`.
- [ ] Счётчик увеличивается при каждом переходе. Проверка и инкремент делаются атомарно (`AtomicInteger` или
  `synchronized`).
- [ ] При достижении лимита переход блокируется и ссылка помечается неактивной.
- [ ] Тест: лимит 3, на четвёртый переход приходит отказ.

### 4. TTL и автоудаление (6)

- [ ] У ссылки есть `createdAt` и `expiresAt`.
- [ ] Фоновая очистка: `ScheduledExecutorService` периодически удаляет просроченные ссылки.
- [ ] Просроченная ссылка не открывается, даже если очистка ещё не сработала (проверка при переходе).
- [ ] Тест с маленьким TTL (1–2 секунды).

### 5. UUID и права на правку/удаление (6)

- [ ] Пользователь идентифицируется по `UUID`, который генерируется при создании и выводится в консоль.
- [ ] Ссылка хранит `ownerUuid`.
- [ ] Правка и удаление проверяют `ownerUuid == currentUser`, иначе выдаётся ошибка «нет прав».
- [ ] Тест: чужой пользователь не может ни изменить, ни удалить ссылку.

### 6. Конфигурация из файла (3)

- [ ] Файл `application.properties` или `config.yaml` лежит в `resources` (или рядом с jar).
- [ ] В нём вынесены TTL по умолчанию, лимит по умолчанию, длина кода, базовый домен, интервал очистки, путь к
  хранилищу.
- [ ] В коде нет «магических» чисел. Если файл не найден или значение некорректно, берётся разумное значение по
  умолчанию.

### 7. Мультипользовательность и несколько ссылок (3)

- [ ] Хранилище устроено как `Map<UUID, User>` и `Map<String, Link>` (или то же в БД/JSON-файле).
- [ ] У одного пользователя может быть много ссылок, команда `list` показывает только его ссылки.
- [ ] Пользователи изолированы друг от друга.

## Расширенные функции (10)

### 8. Уведомления (3)

- [ ] При исчерпании лимита выводится сообщение вроде «Лимит переходов для ссылки X исчерпан».
- [ ] При истечении TTL выводится «Ссылка X истекла и удалена».
- [ ] Уведомление приходит в момент события (при попытке перехода и при очистке), а не молча. Логирование через `Logger`
  /SLF4J.

### 9. Редактирование параметров владельцем (3)

- [ ] Команда `edit <short> --limit N --ttl T` меняет лимит и TTL.
- [ ] Валидация: лимит > 0, TTL > 0, новый лимит не меньше текущего счётчика. Только владелец может править.

### 10. Обработка ошибок (2)

- [ ] Валидация URL (`new URI(...)`, схема http/https, не пустая строка).
- [ ] Проверка границ (отрицательные и нулевые значения, слишком большие числа).
- [ ] Нет необработанных исключений: любая ошибка превращается в понятное сообщение, а не в stacktrace.

### 11. UX CLI (2)

- [ ] Команда `help` с описанием и примерами.
- [ ] Понятные тексты ошибок («Неизвестная команда, введите help»).
- [ ] Приглашение к вводу и подсказки по формату аргументов.

## Качество разработки (10)

### 12. Тесты (3)

- [ ] Не меньше 15 тестов (JUnit 5), либо покрытие не ниже 50% (JaCoCo).
- [ ] Unit-тесты: генератор кода, сервис ссылок, проверка прав, TTL, лимит.
- [ ] Интеграционные сценарии: «создал, открыл N раз, получил блокировку», «создал, подождал TTL, ссылка исчезла»,
  «чужой пользователь не может удалить».

### 13. Архитектура (3)

- [ ] Слои разделены: `core` (модели, сервисы), `infra` (хранилище, конфиг, браузер), `ui` (CLI).
- [ ] Зависимости передаются через интерфейсы и конструкторы (DI): `LinkRepository`, `Clock`, `CodeGenerator`,
  `Notifier`.
- [ ] Нет классов-«богов». `Main` только собирает зависимости.
- [ ] Для тестов TTL удобно использовать подменяемый `Clock`.

- [ ] В README есть раздел «Тестирование».

### 15. Автоматизация (2)

- [ ] GitHub Actions (`.github/workflows/ci.yml`): сборка, тесты, линт.
- [ ] Линтер/форматтер: Spotless или Checkstyle, плюс `.editorconfig`.

1. Каркас проекта (Maven, структура пакетов, конфиг).
